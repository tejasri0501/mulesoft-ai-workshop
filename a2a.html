Module 3: Building the Agent 2 Agent Protocol (A2A)

In this exercise, you will build a Mule A2A application that connects with Agentforce agent.

Exercise: Implement A2A Standard on an existing Agentforce agent

1. Create a new Mule Project:

1.1 Click on in the left menu bar. Select Develop an Integration and create new project with name

Project Name: {initials}-a2a-server-listener

1.2 Select Start from Scratch → Build a Flow

1.3 Select Flow Name 1, Edit in the configuration panel to change it to

Flow Name: a2a-server-listener
→
→
↓

2. Import A2A Connector:

2.1 Click on pom.xml in package explorer and add the following dependency for A2A 

<dependencies>
  <dependency>
    <groupId>com.mulesoft.connectors</groupId>
    <artifactId>mule4-a2a-connector</artifactId>
    <version>0.4.0-BETA</version>
    <classifier>mule-plugin</classifier>
  </dependency>
</dependencies>

3. Configure A2A Connector:

3.1 Click on + in the flow path on the main canvas

3.2 Search for A2A connector

3.3 Select Task Listener operation within the A2A connector, make sure the connector version is 0.4.0-BETA

3.4 Select Task Listener that was just added

3.5 Click on + sign next to Connection Config to add A2A Server configuration

Agent path - /agentforce-agent
Agent Name - ${agent.name}
Agent URL - ${agent.host}/agentforce-agent
Agent Version - 1.0.0
Agent Description - ${agent.description}
→

3.6 Listener Configuration - Click on + , Add

host: 0.0.0.0
port: 8081

click on add

4. A2A Server Configuration:

4.1 Now back on the A2A Server configuration page, add Agent Skills

4.2 Click on + Add in the Agent Skills section and enter the following values,

Skill ID: ${agent.skill.id}
Skill Name: ${agent.skill.name}
Skill Description: ${agent.skill.description}
→

4.3 Add remaining A2A Server configuration ,

Agent Provider Organization: salesforce
Protocol Version: 0.3.0

4.4 Click Add to save the A2A Server configuration

4.5 Store prompt received via A2A Listener in a variable

4.6 Click on + in the flow path right below Task Listener

4.7 Search for variable component and select set variable to add to canvas

Variable name: prompt
Value: Click on fx and add payload.message.parts[0].text

4.8 Add and configure Agentforce Connector to connect to Agentforce agent

4.9 Click on + in the flow path right below variable

4.10 Search for Agentforce connector and select Start agent conversation to add to canvas

4.11 Configure Agentforce Connector Connection

4.12 Select Start agent conversation that was just added and click on + sign next to Connection Config to add connector configuration

Connection name: oAuth Client Credentials
Client Id: provided by MuleSoft
Client Secret: provided by MuleSoft
Token url: provided by MuleSoft

Click Add

→

4.13 Click on the Agent List dropdown, select Agentforce Inventory Agent

4.14 Bypass User: true

4.15 Add and configure Agentforce Connector to connect to pass on the prompt to Agentforce agent

4.16 Click on + in the flow path right below Start agent conversation

4.17 Search for Agentforce connector and select Continue agent conversation to add to canvas

Message: vars.prompt
Session id: enable fx and add payload.sessionId
Message Sequence Number: 10

5. Add Transform Processor:

5.1 Click on + in the flow path below the Continue agent conversation

5.2 Search for Transform and add it to the canvas

5.3 Add following to the Inline Script, 

  %dw 2.0
output application/json
---
{
    id: uuid(),
   "contextId": uuid(),
   "status": {
     "state": "completed"
   },
   "artifacts": [
     {
       "artifactId": uuid(),
       "name": "task",
       "parts": [
         {
           "kind": "text",
           "text": payload
         }
       ]
     }
   ],
   "kind": "task",
   "metadata": {}
}

6. Create configuration.yaml file:

6.1 Create configuration.yaml file in package explorer to store agent properties used by the A2A connector configuration - right click on src/main/resources and select new file: configuration.yaml

6.2 Add below properties to the file 

  agent:
 name: "Agentforce Agent"
 host: "http://localhost:8081"
 description: "Agentforce Agent who is an expert on Kony App, Battery life and Return Process"
 iconUrl: "https://raw.githubusercontent.com/MuleSoft-AI-Chain-Project/
            example-mule-apps/refs/heads/master/a2a-ail-demo/a2a-interaction-agent-app/
            src/main/resources/uiapp/assets/images/agentforceagent.png"
 documentationUrl: "https://developer.salesforce.com/docs/einstein/genai/overview"
 providerOrganization: "Salesforce"
 providerUrl: "https://www.salesforce.com"
 skill.id: "1"
 skill.name: "get-sku"
 skill.description: "Searches for parts information based on the sku provided"

7. Add configuration properties:

7.1 Select /source/main/mule/yourinitials-a2a-agentforce-agent.xml, then click on Open in Code Editor </> in the right top corner of the IDE and add the following line to the xml file as shown below,

<configuration-properties file="configuration.yaml" doc:name="Configuration properties" />

8. Local Validation:

8.1 Select Run Mule Application to run the application locally

8.2 Confirm that the application has started successfully

8.3 Use curl in Terminal to fire the following request 

  curl --location 'http://localhost:8081/agentforce-agent' \
--header 'Content-Type: application/json' \
--data '{
  "jsonrpc": "2.0",
  "id": 12345,
  "method": "message/send",
  "params": {
    "message": {
       "role": "user",
       "kind": "message",
      "parts": [
        {
         "kind": "text",
          "text": "Can you get me parts info for SFP-10G-T-CAT-AO"
        }
      ],
      "messageId": "b69d3e84-7135-47f8-80be-7d0563913082"
    },
    "metadata": {}
  }
}'
