Module 2: Building the Model Context Protocol (MCP)

In this exercise, you will build a Mule application that queries Salesforce for contract product details.

Exercise: Create the MCP Server On top of System API

1. Create a new Mule Project:

1.1 Click on in the left menu bar. Select Develop an Integration and create new project with name

Project Name: {initials}-mcp-salesforce-contract-api

1.2 Select Start from Scratch → Build a Flow

1.3 Select Flow Name 1, Edit in the configuration panel to change it to

Flow Name: mcp-get-contract
→
→
↓

2. Configure MCP Connector:

2.1 Click on + in the flow path on the main canvas

2.2 Search for MCP connector

2.3 Select Tool Listener operation within the MCP connector

2.4 Select Tool Listener processor that was just added

2.5 Click on + sign next to Connection Config to add MCP connector configuration

Connection : Streamable HTTP
Mcp endpoint path : /mcp
Server name : contract-mcp-server
Server version : 1.0.0

2.6 Click on "+" sign next to Listener Configuration to add HTTP configuration

2.7 Enter the following HTTP configuration details:

Host: 0.0.0.0
Port: 8081

2.8 Click on Add again to save the MCP Connection configuration and add tool details

Name: get_contract_details
Description: Retrieve the contract details. The contract is identified by the contract Product Number

2.9 In the Parameters Schema , add the following 

{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "type": "object",
  "properties": {
    "partName": {
      "type": "string",
      "description": "partName"
    }
  },
  "required": ["partName"]
}

2.10 Click on Add in Responses

2.11 In Tool response content drop down Select

Tool response content : Text tool response content

2.12 In Text: Click on fx and add

write(payload,"application/json")

3. Configure System API:

3.1 Click on + in the flow path below the MCP connector

3.2 Search for : HTTP connector

3.3 Select operation Request within the HTTP connector

3.4 Select Request processor that was just added

3.5 Click on + sign next to Connection Config to add HTTP connector configuration & configure the HTTP request configuration

Connection: Request
Protocol: HTTPS
Host: your-system-api-url (just the host name: for example- tn-salesforce-contract-api-tb6jai.5sc6y6-2.usa-e2.cloudhub.io )
Port: 443

3.6 Click on Add

→
→

3.7 Add the following configuration in HTTP Request configuration

Method: POST
Path: /contract
Request - Body:
output json
---
{
partName : payload.partName
}

4. Convert to JSON:

4.1 Click on + in the flow path below the HTTP Request connector

4.2 Search for Transform connector

4.3 Add the following Inline Script

%dw 2.0
output application/json
---
write(payload[0], "application/json")

5. Local Validation:

5.1 Select Run Mule Application to run the application locally

5.2 Confirm that the application has started successfully

5.3 For Testing, add the MCP Server to Mule Dev Agent Configuration

5.3.1 Click on Mule Dev Agent in the left menu bar

5.3.2 Click on Manage MCP Servers → Click on Gear Wheel → Click on Configure MCP Servers and replace the existing configuration with below to add your MCP server to the list, 

{
 "mcpServers": {
   "https://www.npmjs.com/package/@mulesoft/mcp-server": {
     "disabled": false,
     "timeout": 600,
     "type": "streamableHttp",
     "url": "http://127.0.0.1:8686/mcp",
     "headers": {
       "x-mcp-client-id": "A4D_CLIENT"
     }
   },
   "contract-mcp-server": {
     "disabled": false,
     "timeout": 60,
     "type": "streamableHttp",
     "url": "http://localhost:8081/mcp",
     "headers": {
       "Accept": "application/json, text/event-stream"
     }
   }
 }
}

5.3.3 Click on Mule Dev Agent in the left menu bar again

5.3.4 Type following prompt in the

Dev Agent chat - get me contract details for the part - SFP-10G-T-CAT-AO

5.3.5 Validate the response

→
→

6. Deploy MCP Server Application to CloudHub 2.0

6.1 Use Dev Agent to deploy the application to CloudHub 2.0 with the following prompt

Deploy the Contract MCP Server to CloudHub 2.0. Use Mule 4.10.0 runtime

6.2 Use Dev Agent again to validate the deployment by adding your deployed MCP server to the Dev Agent configuration similar to steps listed above in step 5.3

6.3 Validate output & confirm successful deployment
